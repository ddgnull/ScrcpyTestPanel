# 自动化脚本对接契约

本文档是面板与测试脚本之间的**唯一接口约定**，面板侧实现（`test_manager.py`）与模板（`script_template/entry.py`）必须与此一致。

---

## 1. 调用方式

面板通过 `subprocess`（`start_new_session=True`）以 **argv 列表** 启动脚本，不使用 shell，不做字符串拼接。

```bash
{interpreter} {script_path} \
  --serial {SN} \
  --scrcpy-version-id {版本ID 或空串} \
  --project-name {任务名称} \
  --app-version {被测 App 版本} \
  --report-root {报告根目录}
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `--serial` | 是 | adb 设备序列号，脚本所有 adb 操作必须带 `-s` |
| `--scrcpy-version-id` | 否 | 面板当前为该设备生效的 scrcpy 版本 ID，可为空串；仅用于写入报告元信息 |
| `--project-name` | 是 | 任务名称，用于报告目录命名 |
| `--app-version` | 是 | 被测 App 版本，用于报告目录命名 |
| `--report-root` | 是 | 报告根目录绝对路径 |
| `--probe` | 否 | 面板「连通性自检」会调用，脚本应立即返回 0 并打印 `PROBE OK` |

> 面板会额外注入环境变量 `PYTHONUNBUFFERED=1`、`PYTHONIOENCODING=utf-8`，并叠加模板中配置的 `extra_env`。

---

## 2. 目录约定

```
{report_root}/{项目名}/{App版本}/{YYYYMMDD_HHMMSS}/
├── report.html      # 必需
└── result.json      # 建议（后续版本用于结果解析）
```

- 目录由**脚本**创建；面板在启动前已校验 `report_root` 可写。
- 目录段必须清洗：禁用 `/ \ : * ? " < > |`、控制字符与 `..`，长度截断。面板与脚本使用同一套规则（`config_helper.safe_path_segment` / `entry.py:safe_segment`）。
- 同一秒内重复执行由时间戳后缀天然区分；若冲突，脚本可追加 `_2`。

---

## 3. stdout 协议

脚本所有输出走 **stdout**（面板以 `stderr=STDOUT` 合并采集），按行解析：

| 行格式 | 含义 | 面板行为 |
|---|---|---|
| 任意普通行 | 日志 | 以 `[TEST]` 前缀展示，INFO 级 |
| `REPORT_PATH:<绝对路径>` | 报告路径 | 记录，**取最后一次出现**；有该行且文件存在时提供「打开报告」入口 |
| `RESULT_JSON:<绝对路径>` | 结构化结果（预留） | 记录，后续版本解析 |
| `TASK_STATUS:<status>` | 脚本自报终态（预留） | 记录，与退出码取更严格者 |

实现约束（面板侧）：
1. 按字节流增量解码 UTF-8（`errors=replace`）。
2. **按行缓冲**：不完整行挂起到下次拼接，禁止直接切分 chunk —— 否则 `REPORT_PATH` 跨块会丢失。
3. 剥离 ANSI 颜色码与 OSC 序列后再入库。
4. 单行超 2000 字符截断，防止内存与 UI 膨胀。

脚本侧要求：
- 使用 `print(..., flush=True)`，或在启动时依赖 `PYTHONUNBUFFERED=1`。
- 不要输出 ANSI 颜色（面板会剥离，但保留原始控制字符无意义）。
- 不要在报告写出后再打印新的 `REPORT_PATH`（面板取最后一条）。

---

## 4. 退出码

| 退出码 | 含义 | 面板终态 |
|---|---|---|
| `0` | 全部用例通过 | `success` |
| `1` | 存在失败用例 | `failed` |
| `2` | 环境/参数错误，未真正执行用例 | `failed` |
| `130` | 收到 SIGTERM 后优雅退出 | `stopped` |

面板终态优先级（从高到低）：

```
device_offline > timeout > stopped > 退出码（0→success，其它→failed）
```

此外，进程未能拉起（解释器/脚本/权限问题）记为 `start_error`，不进入退出码判定。

---

## 5. 终止约定

面板停止/超时统一走进程组：

1. `SIGTERM` 发给整个进程组（`killpg`）；
2. 宽限 **5 秒**；
3. 未退出则 `SIGKILL`。

脚本必须：
- 捕获 `SIGTERM`，**5 秒内**完成清理（关 Appium session、写报告）；
- 尽力输出 `REPORT_PATH` 与 `TASK_STATUS:stopped` 后以 `130` 退出；
- 不要在被 SIGTERM 后继续跑新用例。

> 只杀主进程会导致 Appium / node 子进程残留并继续占用设备，所以一律杀进程组。

---

## 6. 报告内容要求

报告头部必须写入面板传入的元信息，便于问题复现：

- 设备序列号
- 任务名称
- 被测 App 版本
- scrcpy 版本 ID（可为空）
- 开始时间 / 结束时间
- 最终状态
- 用例清单：名称、结果、详情、耗时

`result.json` 建议结构：

```json
{
  "meta": { "...": "同报告头部" },
  "status": "success|failed|stopped",
  "exit_code": 0,
  "cases": [{"name": "...", "status": "pass|fail", "detail": "...", "ms": 0}]
}
```

---

## 7. 环境隔离

- 面板运行在 `PySide6` 虚拟环境中。
- 测试脚本必须在**独立解释器**中运行（模板字段 `python_interpreter` 指向测试自己的 venv），避免 Appium / pytest 依赖与面板冲突。
- 面板不向脚本传递 `PYTHONPATH`，脚本自行管理导入路径。

---

## 8. 面板侧的启动前校验

启动任务前，面板依次校验：

1. 设备 `adb state == device`（未授权/离线/无权限直接拦截）
2. 模板文件系统校验：`script_path` 存在、`python_interpreter` 可执行、`report_root` 可写
3. 该设备当前没有运行中的测试（单设备互斥）
4. 任务模板 `enabled == true`

任一条不满足，面板拦截并提示，不会启动进程。
